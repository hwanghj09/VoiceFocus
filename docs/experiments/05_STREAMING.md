# 실험 05 | 독립 청크와 상태 유지 처리

## 실시간 후보 측정

동일한 LibriSpeech E02 혼합을 `spk_emb_causal_100`에 입력했다. 지정한 PCM 청크가 쌓이면 이전 추론 완료 시점에 맞춰 하나씩 처리하도록 시뮬레이션했다. 지연은 각 청크의 첫 샘플을 수집하기 시작한 시점부터 그 청크의 추정 파형이 준비될 때까지의 시간이며, 대기열을 포함한다. 마이크, 네트워크, 실제 스피커 출력 지연은 별도로 측정하지 않았다.

| 청크 길이 | RTF | 모델 처리 중앙값 | 시뮬레이션 지연 p95 | SI-SDRi |
| --- | --- | --- | --- | --- |
| 64 ms | 2.124 | 128.52 ms | 5,468.25 ms | −11.20 dB |
| 128 ms | 1.543 | 181.51 ms | 2,837.91 ms | −12.52 dB |
| 256 ms | 1.682 | 426.33 ms | 3,560.47 ms | −16.31 dB |
| 512 ms | 1.618 | 768.92 ms | 3,834.07 ms | −18.72 dB |

causal 체크포인트에 E02의 전체 발화를 한 번에 전달했을 때 RTF는 0.939, SI-SDRi는 −24.73 dB였다. 이 결과로는 RTF 0.5 미만, 지연 100 ms 미만의 두 기준을 충족하지 못해 마이크 스트리밍과 WebRTC의 구현을 보류했다. [측정 JSON](../results/streaming.json)

### 상태를 유지하는 PCM 처리

같은 E02 혼합을 연속 PCM으로 공급했다. 등록 임베딩은 한 번 계산하고, STFT 창과 겹침 합산, 시간축 LSTM 상태를 다음 청크에 이어 전달했다. 지연은 출력 블록의 첫 샘플 수집부터 해당 블록이 준비될 때까지이며, 등록 임베딩 초기화와 네트워크·스피커 지연은 측정에서 제외했다.

| 청크 | A 등록 RTF | A 등록 p95 | B 등록 RTF | B 등록 p95 |
| --- | --- | --- | --- | --- |
| 32 ms | 1.135 | 711.25 ms | 1.723 | 3,623.18 ms |
| 64 ms | 0.746 | 158.07 ms | 0.757 | 174.90 ms |
| 128 ms | 0.533 | 228.88 ms | 0.558 | 243.29 ms |

6개 실행 모두 입력과 같은 80,400샘플을 반환했다. 등록마다 같은 난수 시드를 적용했을 때 causal 일괄 추론과의 최대 절대 샘플 오차는 1.5×10⁻⁷이었다. SI-SDRi는 A 등록에서 −24.74 dB, B 등록에서 +13.45 dB로 청크 크기와 관계없이 일괄 실행과 같았다. 청크 처리 지연은 줄었으며 가장 낮은 p95는 158.07 ms였다. 실시간 기준과 A 등록 분리 품질은 추가 개선이 필요하다. [상태를 유지하는 실행의 측정 JSON](../results/streaming-stateful.json)

독립 청크 방식은 초기 검토 단계이며, 이후 실시간 구현은 별도 실험에서 진행했다. [다음 실험](06_LIVE.md)
