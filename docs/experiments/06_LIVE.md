# 실험 06 | 실시간 마이크와 적응형 검증 창

## 브라우저 마이크 실험

극성이 뒤집힌 예측도 혼합 파형에 맞게 보정한 뒤, 2.5초 문맥에서 후보를 확인해 0.75초 단위로 출력했다. LibriSpeech E02의 동시 발화에서 SI-SDRi는 A 등록 +13.08 dB, B 등록 +13.45 dB였다. G.711 전화 코덱을 적용한 두 화자 겹침 1건에서는 목표 발화도 전부 차단됐다. 목표 화자가 전혀 없는 통화 모사 3건에서는 모든 출력 샘플이 0이었다. 여섯 실행 모두 입력과 같은 길이를 반환했다. [측정 JSON](../results/streaming-live.json)

128 ms 청크를 입력 속도에 맞춰 도착시키는 CPU 시뮬레이션에서 RTF는 0.556–0.883, 출력 블록 지연 p95는 2.71–3.41초였다. 지연은 출력 블록의 처음 샘플이 들어온 시점부터 블록을 내보낼 때까지이며, 브라우저 재생과 네트워크 지연은 시뮬레이션에 포함하지 않았다. Chromium 가상 마이크로 실측 경로의 입력, 처리 출력, 지연 표시, 화면 이동 시 마이크 해제를 검증했다. 통화 목표인 100 ms 미만에 도달하려면 더 짧은 화자 확인 문맥이 필요하다. [재현 방법](../../README.md#실험-재현)

## 초기 근거에 따라 검증 창 선택

짧은 발화에서는 화자 단서가 적어 확인 정확도가 낮아질 수 있다. 1.25초의 후보만 검사했을 때 LibriSpeech E02의 B 화자 발화가 여러 곳에서 끊겼다. 전체 등록 음성과 별도의 2초 구간들을 함께 대조하고, 첫 후보의 에너지가 혼합 음성의 4% 이상일 때만 1.25초부터 출력한다. 그 이후에는 이전 문맥을 추가해 최대 2.5초를 확인한다. 첫 검증이 약한 세션은 기존 2.5초 검증 창을 유지한다. [짧은 발화에서의 화자 검증 연구](https://pmc.ncbi.nlm.nih.gov/articles/PMC10280689/)

128 ms 청크, CPU 두 스레드로 21개 조건을 측정했다. E02 겹침에서 새 출력 지연 p95는 A 등록 1.58초, B 등록 1.73초였다. 이전 측정의 SI-SDRi `+13.08 / +13.45 dB`와 새 측정의 `+13.01 / +13.45 dB`를 비교했다. 전체 21개 조건의 개별 p95 중앙값은 같은 장비에서 다시 실행한 기존 버전 2.79초, 새 버전 2.77초였다. 근거가 부족한 통화는 긴 검증 창을 쓰며, 처리 부하가 높으면 더 늦어질 수 있다.

등록 화자가 없는 세 조건의 출력은 모두 0이었다. A가 약 2초 말한 뒤 B만 남기는 추가 예제에서도 목표 화자가 없던 구간의 출력은 0이었다. 이 예제 전체의 SI-SDRi는 기존 +15.31 dB, 새 방식 +11.08 dB였다. 소음 조건 한 건에서는 목표가 쉬는 동안 혼합 대비 −24.06 dB의 신호가 남았다. `target-leaves`는 LibriSpeech `a-1.wav`의 첫 2초와 `b-4.wav`의 2초 이후를 잇고, 음량을 0.7배로 맞춰 `a-0.wav`를 등록한 예제다. [측정 JSON](../results/streaming-adaptive.json)

로컬 WebSocket에서 같은 WAV를 보내고 `ready`까지 걸린 시간은 첫 연결 8.33초, 같은 프로세스의 다음 연결 0.35초였다. 가중치는 재사용하고 화자 확인 상태는 새 세션마다 계산한다. 이 등록 처리 시간과 통신·브라우저 재생 시간은 위 CPU 출력 지연에 포함되지 않는다. 100 ms 목표는 아직 충족하지 못했다. [실험 재현](../../README.md#실험-재현)
