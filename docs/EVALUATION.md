# 평가 결과

## 체크포인트와 재현 환경

파일 데모에 REAL-TSE 공식 `spk_emb_100`을 사용했다. 주 WeSep 저장소의 최신 버전은 사전 학습 모델 배포를 준비 중이다. REAL-TSE의 소스는 `d9ed77d`, WeSpeaker는 `8f53b64`에서 고정했다. ZIP의 SHA-256을 검사한 뒤 필요한 체크포인트만 추출한다. 추론 코드 및 REAL-TSE 학습 파라미터의 Apache-2.0 조건과, 내장 ECAPA 파라미터에 적용되는 별도 업스트림 조건은 각 프로젝트 문서를 참조한다. [WeSep](https://github.com/wenet-e2e/wesep) · [REAL-TSE 및 체크포인트 조건](https://github.com/REAL-TSE/wesep-real-tse#2-download-pretrained-model) · [WeSpeaker](https://github.com/wenet-e2e/wespeaker)

2026-11-25에 Python 3.12, PyTorch CPU 2.7.1, Intel Xeon Platinum 8573C, CPU 할당량 2개, 추론 스레드 2개에서 측정했다. 자연 음성은 LibriSpeech test-clean 화자 6930과 260의 독립 발화 6개씩을 사용했다. 합성 음성은 eSpeak NG 1.52.0의 두 음성으로 같은 문장을 읽게 했다. LibriSpeech는 OpenSLR에서 CC BY 4.0으로 제공하며, 원본과 파생 음성은 이 저장소에 보관하지 않는다. 두 화자 표본이므로 일반화 성능을 나타내지 않는다. [OpenSLR SLR12](https://www.openslr.org/12/) · [실험 재현](../README.md#실험-재현)

## 통화 녹음에서 등록 화자 추출

ICASSP 2023 Personalized DNS Challenge는 등록 음성으로 주 화자와 주변 화자를 구별하는 조건을 평가한다. Gated Cross-Attention 연구는 목표가 말할 때의 분리 품질과 목표가 말하지 않을 때의 출력 에너지를 각각 평가한다. VoiceFocus의 통화 모드는 이 두 조건을 나눠 측정하며, REAL-TSE와 WeSpeaker로 분리 후보의 신원을 확인한 뒤 검증에 실패한 블록을 음소거한다. [ICASSP 2023 Personalized DNS Challenge](https://www.microsoft.com/en-us/research/publication/icassp-2023-deep-noise-suppression-challenge/) · [Gated Cross-Attention](https://doi.org/10.3390/electronics13112046)

LibriSpeech test-clean의 다섯 화자를 세 쌍으로 조합했다. 등록 클립과 섞은 발화는 서로 다른 녹음이다. 측정 조건은 서로 겹친 발화의 RMS 차이 6 dB, 저역 잡음이 섞인 발화, 전후에 방해 화자만 말하는 구간, 목표 화자가 전혀 없는 구간이다. 대부분의 경우 300–3400 Hz 대역과 8 kHz G.711 μ-law 변환을 거쳐 같은 16 kHz 길이의 WAV로 평가했다. 저역 잡음 혼합은 16 kHz를 사용했다. 무음은 출력 샘플이 모두 0인지 검사했고, 무음 출력의 SI-SDR은 집계에서 제외했다. [원본 녹음 · OpenSLR SLR12 · CC BY 4.0](https://www.openslr.org/12/) · [재현 방법](../README.md#실험-재현)

| 측정 조건 | REAL-TSE 기본 | 통화 모드 |
| --- | ---: | ---: |
| G.711 겹침 `a-b-overlap`의 B 화자 SI-SDR | −19.87 dB | +10.79 dB |
| 같은 구간에서 A 화자에 대한 SI-SDR | +8.54 dB | −28.05 dB |
| `1320-3575-pauses`의 목표 무발화 구간 출력 에너지, 혼합 대비 | −2.98 dB | −22.60 dB |
| 목표 화자가 전혀 없는 파일의 완전 무음 | 0/3 | 3/3 |

목표 화자가 말한 15건 중 저역 잡음이 섞인 1건에서 목표 발화까지 모두 음소거됐다. 다른 저역 잡음 샘플에서는 무발화 구간이 무음이 됐으며 목표 SI-SDR은 +11.93 dB에서 +8.27 dB로 낮아졌다. 발화가 겹치거나 빠르게 교대하는 구간에서는 타인의 소리나 잡음이 남을 수 있다. [전체 측정 CSV](results/calls.csv)

이 검증은 녹음 파일 전체와 1.5초 문맥을 사용한다. 실시간 자체 웹 통화에서는 같은 두 품질 지표를 지연과 함께 다시 측정해야 한다. SpeakerBeam-SS는 인과형 Conv-TasNet에 상태 공간 모델을 결합해 실시간 목표 화자 추출의 계산량을 줄였다. [SpeakerBeam-SS](https://www.isca-archive.org/interspeech_2024/sato24_interspeech.html)

## 실시간 후보 측정

동일한 LibriSpeech E02 혼합을 `spk_emb_causal_100`에 입력했다. 지정한 PCM 청크가 쌓이면 이전 추론 완료 시점에 맞춰 하나씩 처리하도록 시뮬레이션했다. 지연은 각 청크의 첫 샘플을 수집하기 시작한 시점부터 그 청크의 추정 파형이 준비될 때까지의 시간이며, 대기열을 포함한다. 마이크, 네트워크, 실제 스피커 출력 지연은 별도로 측정하지 않았다.

| 청크 길이 | RTF | 모델 처리 중앙값 | 시뮬레이션 지연 p95 | SI-SDRi |
| --- | --- | --- | --- | --- |
| 64 ms | 2.124 | 128.52 ms | 5,468.25 ms | −11.20 dB |
| 128 ms | 1.543 | 181.51 ms | 2,837.91 ms | −12.52 dB |
| 256 ms | 1.682 | 426.33 ms | 3,560.47 ms | −16.31 dB |
| 512 ms | 1.618 | 768.92 ms | 3,834.07 ms | −18.72 dB |

causal 체크포인트에 E02의 전체 발화를 한 번에 전달했을 때 RTF는 0.939, SI-SDRi는 −24.73 dB였다. 이 결과로는 RTF 0.5 미만, 지연 100 ms 미만의 두 기준을 충족하지 못해 마이크 스트리밍과 WebRTC의 구현을 보류했다. [측정 JSON](results/streaming.json)

### 상태를 유지하는 PCM 처리

같은 E02 혼합을 연속 PCM으로 공급했다. 등록 임베딩은 한 번 계산하고, STFT 창과 겹침 합산, 시간축 LSTM 상태를 다음 청크에 이어 전달했다. 지연은 출력 블록의 첫 샘플 수집부터 해당 블록이 준비될 때까지이며, 등록 임베딩 초기화와 네트워크·스피커 지연은 측정에서 제외했다.

| 청크 | A 등록 RTF | A 등록 p95 | B 등록 RTF | B 등록 p95 |
| --- | --- | --- | --- | --- |
| 32 ms | 1.135 | 711.25 ms | 1.723 | 3,623.18 ms |
| 64 ms | 0.746 | 158.07 ms | 0.757 | 174.90 ms |
| 128 ms | 0.533 | 228.88 ms | 0.558 | 243.29 ms |

6개 실행 모두 입력과 같은 80,400샘플을 반환했다. 등록마다 같은 난수 시드를 적용했을 때 causal 일괄 추론과의 최대 절대 샘플 오차는 1.5×10⁻⁷이었다. SI-SDRi는 A 등록에서 −24.74 dB, B 등록에서 +13.45 dB로 청크 크기와 관계없이 일괄 실행과 같았다. 청크 처리 지연은 줄었으며 가장 낮은 p95는 158.07 ms였다. 실시간 기준과 A 등록 분리 품질은 추가 개선이 필요하다. [상태를 유지하는 실행의 측정 JSON](results/streaming-stateful.json)

### 브라우저 마이크 실험

극성이 뒤집힌 예측도 혼합 파형에 맞게 보정한 뒤, 2.5초 문맥에서 후보를 확인해 0.75초 단위로 출력했다. LibriSpeech E02의 동시 발화에서 SI-SDRi는 A 등록 +13.08 dB, B 등록 +13.45 dB였다. G.711 전화 코덱을 적용한 두 화자 겹침 1건에서는 목표 발화도 전부 차단됐다. 목표 화자가 전혀 없는 통화 모사 3건에서는 모든 출력 샘플이 0이었다. 여섯 실행 모두 입력과 같은 길이를 반환했다. [측정 JSON](results/streaming-live.json)

128 ms 청크를 입력 속도에 맞춰 도착시키는 CPU 시뮬레이션에서 RTF는 0.556–0.883, 출력 블록 지연 p95는 2.71–3.41초였다. 지연은 출력 블록의 처음 샘플이 들어온 시점부터 블록을 내보낼 때까지이며, 브라우저 재생과 네트워크 지연은 시뮬레이션에 포함하지 않았다. Chromium 가상 마이크로 실측 경로의 입력, 처리 출력, 지연 표시, 화면 이동 시 마이크 해제를 검증했다. 통화 목표인 100 ms 미만에 도달하려면 더 짧은 화자 확인 문맥이 필요하다. [재현 방법](../README.md#실험-재현)

### 초기 근거에 따라 검증 창 선택

짧은 발화에서는 화자 단서가 적어 확인 정확도가 낮아질 수 있다. 1.25초의 후보만 검사했을 때 LibriSpeech E02의 B 화자 발화가 여러 곳에서 끊겼다. 전체 등록 음성과 별도의 2초 구간들을 함께 대조하고, 첫 후보의 에너지가 혼합 음성의 4% 이상일 때만 1.25초부터 출력한다. 그 이후에는 이전 문맥을 추가해 최대 2.5초를 확인한다. 첫 검증이 약한 세션은 기존 2.5초 검증 창을 유지한다. [짧은 발화에서의 화자 검증 연구](https://pmc.ncbi.nlm.nih.gov/articles/PMC10280689/)

128 ms 청크, CPU 두 스레드로 21개 조건을 측정했다. E02 겹침에서 새 출력 지연 p95는 A 등록 1.58초, B 등록 1.73초였다. 이전 측정의 SI-SDRi `+13.08 / +13.45 dB`와 새 측정의 `+13.01 / +13.45 dB`를 비교했다. 전체 21개 조건의 개별 p95 중앙값은 같은 장비에서 다시 실행한 기존 버전 2.79초, 새 버전 2.77초였다. 근거가 부족한 통화는 긴 검증 창을 쓰며, 처리 부하가 높으면 더 늦어질 수 있다.

등록 화자가 없는 세 조건의 출력은 모두 0이었다. A가 약 2초 말한 뒤 B만 남기는 추가 예제에서도 목표 화자가 없던 구간의 출력은 0이었다. 이 예제 전체의 SI-SDRi는 기존 +15.31 dB, 새 방식 +11.08 dB였다. 소음 조건 한 건에서는 목표가 쉬는 동안 혼합 대비 −24.06 dB의 신호가 남았다. `target-leaves`는 LibriSpeech `a-1.wav`의 첫 2초와 `b-4.wav`의 2초 이후를 잇고, 음량을 0.7배로 맞춰 `a-0.wav`를 등록한 예제다. [측정 JSON](results/streaming-adaptive.json)

로컬 WebSocket에서 같은 WAV를 보내고 `ready`까지 걸린 시간은 첫 연결 8.33초, 같은 프로세스의 다음 연결 0.35초였다. 가중치는 재사용하고 화자 확인 상태는 새 세션마다 계산한다. 이 등록 처리 시간과 통신·브라우저 재생 시간은 위 CPU 출력 지연에 포함되지 않는다. 100 ms 목표는 아직 충족하지 못했다. [실험 재현](../README.md#실험-재현)

## 노래 화음

Choral Singing Dataset에서 무반주 두 사람이 서로 다른 음을 동시에 부르는 6초 구간을 세 곡에서 골랐다. 각 가수를 순서대로 등록하되 혼합 구간과 겹치지 않는 다른 악절을 썼다. 기존 REAL-TSE와 새 노래 화음 모드를 혼합과 등록에 각각 같은 악절을 사용했다. 분리 결과의 SI-SDR은 목표 트랙에 대해, 제거 결과의 SI-SDR은 남길 트랙에 대해 원본 믹스 대비 개선량을 계산했다. [원본 녹음 · Choral Singing Dataset · CC BY-NC 4.0](https://zenodo.org/records/2649950)

| 곡 | 등록 | 기존 제거 SI-SDRi | 노래 화음 제거 SI-SDRi |
| --- | --- | ---: | ---: |
| Locus Iste | 소프라노 | −23.28 dB | +20.24 dB |
| Locus Iste | 알토 | −45.49 dB | +20.21 dB |
| El Rossinyol | 테너 | −21.34 dB | +18.52 dB |
| El Rossinyol | 베이스 | −28.07 dB | +18.51 dB |

동일한 여섯 선택에서 추출과 제거가 모두 개선된 횟수는 1회에서 6회가 됐다. 다른 악절에서 같은 가수로 재시험한 여섯 선택도 추출과 제거가 개선됐다. 추가 구간의 제거 SI-SDRi는 +16.22~+28.24 dB였다. 테너를 빼도록 지정한 Niño Dios 원래 예제에서는 테너 성분이 약 38.65 dB 줄고 소프라노는 약 0.12 dB 줄었다. 이 평가는 무반주 두 사람의 구간에 한정되며, 반주가 겹치거나 음역이 비슷한 가수의 결과는 별도 평가가 필요하다. ### 비슷한 음높이와 음량 차이

같은 데이터에서 이전에 쓰지 않은 가수 조합과 6초 혼합을 골랐다. 세 혼합은 같은 성부의 두 사람이 부른 구간이고, 나머지 세 혼합은 다른 성부의 음량 차이를 RMS 기준 9 dB로 맞췄다. 각 혼합에서 두 가수를 차례로 제거했다. 등록에는 혼합과 겹치지 않는 악절을 썼다. 동일한 분리 후보에 대해 뺄 가수만 등록했을 때와 뺄 가수 및 남길 가수를 모두 등록했을 때를 비교했다. 제거할 후보가 목표 가수에 대해 더 높은 SI-SDR을 보이면 가수 선택이 맞은 것으로 집계했다. [원본 녹음 · Choral Singing Dataset · CC BY-NC 4.0](https://zenodo.org/records/2649950)

| 조건 | 뺄 가수 등록 | 두 가수 등록 |
| --- | ---: | ---: |
| 같은 성부에서 올바른 가수 선택 | 5/6 | 6/6 |
| 음량 차이 9 dB에서 올바른 가수 선택 | 4/6 | 6/6 |
| 남긴 음성의 SI-SDRi 중앙값 | +10.15 dB | +10.47 dB |

El Rossinyol에서 같은 음을 부른 두 테너 중 테너 2를 뺄 때, 남길 테너 4의 SI-SDR이 −9.67 dB에서 +11.83 dB로 올랐다. 이 측정은 무반주 두 가수에 한정된다. 같은 음을 부르는 세 혼합 모두 올바른 가수를 골랐어도 남긴 음성에서 분리 오차가 남았다. [전체 측정 CSV](results/harmony-accuracy.csv) · [재현 방법](../README.md#테스트)
