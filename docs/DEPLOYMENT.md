# 데모 배포와 운영

Linux CPU 호스트에서 Python 3.11–3.12와 `venv`, Node.js 22.12 이상, Git, curl을 준비합니다. 일부 Python 패키지를 소스에서 설치하는 환경은 C 컴파일러도 필요합니다. 설치는 `.venv`에 CPU용 PyTorch와 Python 패키지를 설치하고, 기존 모델 스크립트의 고정 버전과 체크섬을 사용합니다. 프런트엔드는 `npm ci`로 빌드합니다. REAL-TSE 체크포인트 묶음만 약 1 GB이므로 런타임과 모델 파일까지 저장할 여유 공간을 확보하세요.

```bash
bash scripts/setup_demo.sh
bash scripts/serve_demo.sh
```

기본 주소는 `http://127.0.0.1:8000`입니다. 기존 Python 3.11–3.12 가상 환경을 재사용하려면 두 명령에 `PYTHON`으로 실행 파일 경로를 지정하세요. 검증된 REAL-TSE 아카이브를 이미 받은 경우 `VOICEFOCUS_CHECKPOINT_ARCHIVE`로 경로를 넘길 수 있습니다. 포트는 `VOICEFOCUS_PORT`, 바인드 주소는 `VOICEFOCUS_HOST`로 지정합니다.

별도 기기에서 사용하려면 HTTPS와 인증을 제공하는 역방향 프록시 뒤에 앱을 두세요. 프록시는 같은 호스트에서 프런트엔드와 API를 제공하고, 원래 `Host`를 유지하며 `/ws/v1/stream`과 `/ws/v1/calls`의 WebSocket 업그레이드를 전달해야 합니다. 앱 실행 스크립트는 작업 결과와 통화방을 공유할 수 있게 Uvicorn 워커 하나를 사용합니다. 프로세스가 재시작되면 진행 중인 통화와 임시 결과가 사라집니다.

## 배포 확인

```bash
curl -fsS http://127.0.0.1:8000/healthz
curl -fsS http://127.0.0.1:8000/api/v1/models
```

`/healthz`가 `ok`를 반환하면 HTTP 서버가 동작합니다. `/api/v1/models`에서 각 모델의 `available`과 `automatic_available`, `live_available` 값을 확인하세요. 실제 추론을 확인하려면 동의받은 WAV나 README의 공개 예제를 사용해 음성 추출, 비교 재생, 결과 삭제까지 진행합니다. [예제와 브라우저 테스트](../README.md#테스트)

## 음성 보관과 접근 범위

- 파일 추출 요청에 혼합 WAV와 등록 WAV가 포함됩니다. 업로드를 읽을 때 생성되는 임시 파일은 요청이 끝날 때 닫고, 추론 작업의 WAV는 작업 종료 시 임시 디렉터리와 함께 정리합니다. 호스트가 강제로 중단된 경우에는 시스템 임시 디렉터리에 파일이 남을 수 있습니다.
- 비교용 원본과 추출·제거 결과는 서버 메모리에 보관됩니다. 작업 종료 15분 후 조회가 만료되며, 만료된 결과는 10초마다 정리됩니다. **추출 결과 삭제**로 완료 작업의 메타데이터와 음성을 즉시 지울 수 있습니다. 브라우저에서 내려받은 파일은 사용자가 직접 관리합니다.
- 작업 UUID를 아는 클라이언트는 해당 작업을 조회하거나 삭제할 수 있습니다. UUID가 포함된 URL은 접근 권한처럼 다루세요. 실행 스크립트는 Uvicorn 요청 로그를 끕니다. 역방향 프록시 로그에서도 작업 URL을 기록하지 않도록 설정하세요.
- 웹 통화의 기본 음성은 두 브라우저 사이로 전달됩니다. **VoiceFocus 켜기**를 선택한 동안에는 수신 음성과 등록 WAV가 서버 메모리에서 처리됩니다. 사용 전에 상대의 동의를 받고 방 코드는 상대에게만 공유하세요.

## 현재 성능 범위

웹 통화 실험은 직접 연결이 가능한 같은 네트워크를 대상으로 합니다. 서버당 등록 화자 필터 한 세션을 처리하며, CPU 실험에서 필터 출력 지연 p95는 2.71–3.41초였습니다. 짧거나 겹친 발화에서는 등록된 목소리까지 약해지거나 음소거될 수 있습니다. 화음 분리는 두 사람의 무반주 녹음으로 평가했습니다. [평가 데이터와 측정 조건](EVALUATION.md)
